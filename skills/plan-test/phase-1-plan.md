# Phase 1 — 调查与写 plan

**目的**：基于 `{ACCEPTANCE_FILE}` 先调查、再实践、后写 plan，**当前片代码级可执行**。**没有调查，就没有发言权**：论断来自真读代码，假设来自真跑实践。

- 可基于 phase-A 草案调查，不把待定假设写成用户已批准事实；涉及用户决定时先完成决策所需的定向调查，再提问（RULES R11）。
- delivery 先读 `references/delivery-slices.md`；未来片可缓细节，不能缓决定整体可行性的调查。

## 步骤
1. **调查现状**（纪律 `methods/research-method.md`，不另写架构文档）
   - **围绕主要矛盾圈定调查范围**：只查解法触碰的模块/链路/依赖。
   - **解剖麻雀**：最核心改动模式选一条典型调用链从入口挖到底，写成通用模式。
   - 不可行或与 acceptance 冲突 → 先查范围内替代；需改变目标/范围时附决策简报升级，不硬写 plan。
2. **最佳实践调研（不可跳过）**：**反对本本主义**，每个外部方案必须附本项目适配分析（前提同异、照用/改造/不用）。
3. **实践先行**
   - 关键假设只列决定成败且静态读不出的。
   - 整体与当前片关键假设**当场写可丢弃 spike 真跑验证**；"读过源码应该支持/理论上可行"不算数。
   - **主要矛盾的 spike 必须走生产接缝**，否则只算组件级证据，标注"未经生产入口验证"（RULES R4）。
   - 假设不成立 → 改方案（必要时回 phase-A 和用户重新讨论方向）。
   - spike 代码即弃，不滚成实现，不为验证造系统（RULES R14）。
   - spike 只跑最小一次、只证关键假设；plan 阶段不做矩阵/多样本/真人多场景等高成本验证（RULES R16）。
4. **写 plan**：`{PLANS_DIR}/<按需求命名的新文件夹>/plan.md`。

## plan.md 各节
1. 矛盾分析：主要矛盾/方面、最小验证动作、当前片价值里程碑。
2. 现状调查：麻雀解剖、技术债，论断附代码证据（文件:行号）。
3. 方案与权衡：选型理由、放弃的备选、权衡。
4. 关键假设与实践证据：假设 / spike 命令 / 实际输出 / 结论。
5. 交互边界：授权来源、范围/预算/操作边界、停止条件、自决项、待决项及决策简报。
6. 关联 AC：AC-n（决定性/次要）各有任务覆盖。
7. 文件影响（职责/现状/改动）；入口链、数据流/持久化、外部依赖、停止追踪点（FULL 见 `full/phase-1-plan.md`）。
8. `Complexity inventory`：新增复杂度须绑定 AC/风险，否则 minimality pass 删除（ponytail）。
9. 切片：全部 MUST AC → 负责片（跨片列最终组合验证）；每片交付表、未来片待细化项按 delivery-slices；技术准备不能冒充交付片。
10. 当前片任务：标 slice ID、AC、矛盾地位；每点写**改哪个文件 → 哪段/哪个函数 → 怎么改 → 改成什么样**、现状、依赖；验证栏先写"什么算对"（RULES R3）。**各片内任务排序 = 最短价值路径优先**：里程碑前只排直接依赖，加固/次要 AC 排其后，不借依赖排序前置仪式任务。

## 铁律与出口
- 不得静默减少用户已批准的外部行为（RULES R13）。
- "100% 代码可执行"= 当前片 required AC 有确定实现与验证出口 + 整体 AC 有负责片 + 整体关键假设已验证；不含未来片待细化项，不表示零缺陷。
- 全部"必须" AC 有负责片；当前片任务到代码级；整体与当前片关键假设有实测证据；未来片待细化项明示 → phase-2。
