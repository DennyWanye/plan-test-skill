# 用户注意力与决策

三个入口在开场读取本文件；它统一各阶段的交互语义。目标是让用户决定目标和重要取舍，Agent 承担调查、计划、执行、修复与验证。保留既有验收和授权边界，不新增机器门或批准手续。

## 先识别已有意图与授权

从当前请求、历史明确决定和项目约束整理目标、MUST AC、预算/操作边界、停止条件，写在现有 plan 的“交互边界”节即可，不另建账本。

- **一条龙 / 已授权执行**：先完成范围内调查、plan 和挑战；现有授权已覆盖最终方案且没有重要未决取舍时，展示简短方案摘要后直接执行，不再请求 acceptance、plan、阶段切换或 demo 的重复批准。
- **先计划并等确认**：完成调查、验收标准、可执行 plan 与决策简报后，合并为一次 review，明确停在实现之前。不能因等待时间长、用户沉默或“节省注意力”自动执行。
- **plan-bs 共创**：保留用户想讨论的体验，只问尚未明确的目标/价值取舍；已回答的内容不换措辞重问。共创和最终 review 不授权业务实现。
- **plan-task / 续接**：先读取指定 plan、批准记录和未完成项。已有授权与当前目标一致则继续；只有标记缺失但能找到实际定稿/授权证据时，补齐标记并注明来源。没有事实依据不得伪造 finalized 或批准记录。
- **停止 / 交接**：用户明确要求停止或只做指定收尾时，按该边界保存现状与未完成项；流程的“必须修完”不能覆盖停止指令。

## 什么由 Agent 处理

技术选型、文件组织、执行顺序、局部重构、测试诊断，以及**保持目标、MUST AC、用户行为、保障等级和预算/操作边界的计划修订**，由主 Agent 调研后决定并记录依据。方案有多个不等于必须让用户选择。执行子代理发现 plan 缺陷交回主 Agent，主 Agent 按 A2 补调查、挑战和验证后继续。

以下情况才产生用户决策：真实意图无法从现有信息确定；可感知目标/行为改变或缩减 AC；明显新增成本、扩大范围/可信边界；所需操作没有授权；必须由用户提供的资源、凭据或人工动作；用户明确要求停下确认。具体批准仍受环境和项目硬约束约束。

提问前先完成能自行查明的事实与安全可逆准备；不要把“选哪个库”“要不要继续修”“能否切阶段”作为默认问题。文件、已有记录、工具输出能回答的，不问用户。

## 决策前先调研

只调查会改变这次选择的信息：当前实现/依赖约束、可行性、迁移或兼容影响、成本、失败后恢复。优先本次代码/日志和官方资料；易变的外部事实核对当前来源与日期。运行时假设用授权范围内的最小 spike 验证。

**调查停止条件**：推荐方案和真实备选已能比较，关键未知项已验证或已明确其对选择的影响。不要为凑选项、精确工期或“100% 确定”无限研究。如果所缺的就是用户目标、资源或权限，先给已有事实和缺口，问最小问题，不要求不可能的预先验证。

在用户真正需要决策的消息里给出简短**决策简报**（详细证据链接到 plan，用户不必先通读文件）：

1. **要决定什么、为什么需要你**：用行为/交付结果解释，区分价值取舍、范围变化与权限缺口。
2. **已查明的事实**：关键证据、来源和检查日期；明确哪些是推断。
3. **可行选项与推荐**：通常 2–3 个，只保留真实可选方案；说明推荐如何满足用户目标。若只有一个可行方案，如实说明，不制造陪衬选项。
4. **代价和后果**：用户可见差异、范围/时间/费用、风险、可逆性/回滚。无依据的估计写区间或“未知”，不给假精度。
5. **剩余未知与最小问题**：未知如何影响选择、能怎样补证；用户只需回答哪项。说明已完成的准备、回答前继续什么、哪部分等待。

不得先让用户选方向，选完才发现关键限制。也不得拿“调研需要付费/生产写入”推导已有权限：准备具体可审阅的操作与回滚方案后，把所缺权限作为这次决策的一部分。

## 等待与恢复

- 不相关的重要问题尽可能合并在一次 review；有依赖的问题先解决上游，不把未验证的后续选择一起抛出。短问清真实目标是合理交互，不设机械的“最多问 N 次”。
- 等待时继续已授权且独立的任务；依赖用户答案的分支保持等待，不用默认值或超时视为同意。没有独立工作时明确说明卡点，结束本轮等待答复。
- **BLOCKED 是交付状态，不自动等于向用户求助**。可自行修复的失败按现有轮次上限诊断、修复、重测；真外部阻塞或达到出口阈值时，附已试方法、结果、推荐出口和最小用户动作。保持 required 未通过状态，不能靠减少提问把它改为 PASS。
- 跨会话先读取 plan/journal/handoff 的授权、决策、open findings、下一步和测试身份；依现有内容/环境身份与影响范围规则复验。身份不可核对则重测，不向用户索要已有记录能恢复的信息，不重开 run 来清除历史失败。

## 进度与收尾

里程碑展示实物与结果，用“已完成什么 / 现在验证什么 / 是否需要你”说明状态；demo 是可异步纠偏的进度展示，除非事先约定用户验收，否则不等待确认。发现重要行为偏差时仍先决策再改变目标。

门清单、内部审计和计时留在 plan/journal；对用户只说明影响结果的门与实际限制，不逐阶段倾倒检查表。遵守所在环境的进度频率要求；没有可靠 ETA 就报告已知进展与下一检查点。

在现有 retro 追加一行：本次哪些用户打断不可避免、哪些可由预先调查/复用授权消除（能准确数才记次数）。不新增计数器或门禁。未经真实后续运行，不宣称注意力下降了某个百分比。
