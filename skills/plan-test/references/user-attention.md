# 用户注意力：授权与续接细则

核心见 RULES R11；按需细则，开场不读。不新增机器门或批准手续。

## 授权
- plan「交互边界」写目标、MUST AC、预算/操作边界、停止条件、自决项与待决项，不另建账本。
- 已授权执行：先调查/plan/挑战，摘要后执行，不重复要 acceptance/plan/阶段/demo 批准。
- 先计划等确认：合并一次 review 停在实现前；等待久或沉默不自动执行。
- plan-bs：只问未明确的目标/价值取舍，已答不换措辞重问；共创与 review 不授权实现。
- 停止：按用户边界保存现状与未完成项，"必须修完"不覆盖停止。
- 需求占位/模糊先澄清；评测子代理发现 plan 缺陷只上报，交主 Agent 走 A2（仍需挑战），不自行改代码（RULES R15）。

## 提问前
- 多方案≠必须让用户选。先做能自查的事实与安全可逆准备；文件/记录/工具输出能答的不问；选库/继续修/切阶段不是默认问题。
- 只查会改变选择的信息，优先本次代码/日志与官方资料，易变事实核来源日期，运行时假设用最小 spike；推荐与真实备选可比、关键未知已验证即停，不为凑选项、精确工期或 100% 确定无限研究；缺目标/资源/权限时给事实与缺口问最小问题，不要求不可能的预先验证。
- 不得选完方向才发现关键限制；不从"需付费/生产写入"推导权限，备好操作与回滚把权限纳入决策。
- 决策简报格式只在交接单 H3，消息结构按 H0。
- 批次未回不发新请求（新阻塞除外）；有依赖先解上游；阻塞全部工作才立即问；短问清目标不设提问次数上限；"全按默认"=逐项批准，原话 hash 入账一次。可感知标的差异（模型/端口/模式）定稿前复述。

## 等待与续接
- BLOCKED 升级消息按 R10 `MODE: light` 评估（判据 RULES R9）。
- 等待时做已授权独立工作，依赖答案的分支不以默认或超时当同意；无独立工作则说明卡点结束本轮。
- 续接：先读 plan/journal/handoff 的授权、决策、open findings、下一步、测试身份；按 RULES R8 复验。
- plan-task：授权与当前目标一致则继续；标记缺失但有定稿/授权证据才补标并注来源，不得伪造 finalized 或批准。
- 身份不可核对就重测；已有记录能恢复的不问用户；不重开 run 清除历史失败。

## 汇报
- 用"已完成什么/现在验证什么/是否需要你"说明；片内与整体分报；含 demo 入口时按 R10 `MODE: full` 评估。
- 门清单/审计/计时留 journal，对用户只说影响结果的门与限制；遵守环境汇报频率，无可靠 ETA 报进展与下一检查点。
- demo 给实物（URL/截图/命令）；可操作入口按 R10 `MODE: full` 评估；重要行为偏差先决策。
- retro 追加一行：哪些打断不可避免、哪些可消除（不新增计数器或门禁）；未经真实运行不宣称注意力降幅。
