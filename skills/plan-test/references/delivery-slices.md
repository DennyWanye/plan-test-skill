# 按可交付能力切片

delivery 规划/执行时读。片是 Agent 交付单位，不新增批准点/机器门/授权。OPS/program/超限见 `conditional/delivery-slices.md`。

## 整体 → 片 → 任务
- 整体计划定目标/全部 MUST AC/边界/架构/片依赖；每条 MUST 有负责片，跨片能力写组合验证；未执行项始终保留，不能靠拆片消失。
- 片 = 已验证产物上加一项可用能力；审查：后续不做，累计产物能否经实际入口使用并验证承诺？独立验收不等于脱离所有前序依赖重新运行。
- 任务在片内；只做一层不算片，必要底层准备归入最早消费它的切片。小需求可以只有一片；体量上限只防过大片；沿架构扩展不反复重写。

## 交付表（写进 plan）
- ID/能力/AC：只覆盖部分 AC 时写本片断言与最终负责片。
- 真实入口：输入→可观察结果及运行环境；应用 UI/CLI 命令/API 真实请求/库真实消费者（库是交付物不造 UI）；仅 mock/内部自测/流程 completed 不足证明；目标要真实 provider/设备时替身只算准备证据（RULES R4）。
- 最小决定性验证：实现前写好输入/独立预期/通过条件，含安全正确性（RULES R3）。
- 依赖与边界：前提能力/承诺边界/外部资源与授权是否具备。
- 保留与回退：前片哪些行为必须继续成立/受影响回归/安全恢复。

## 逐片细化
- 整体成败假设（架构/数据迁移/外部能力/成本/跨片接口）先调查，不足则最小 spike，不能留待后续就称可行。
- 当前片完成代码级调查/任务/oracle/挑战闭环再实施；未来片可缓函数级细节，须标待细化项/触发时点/风险，不写成已验证；进该片前补调查/spike/挑战/基线差异，范围内技术细化不重新索取批准。

## 每片闭环
1. 核前序/授权/前提，跨片依赖尚未通过则不启动依赖实现；打通真实入口最短链路，实际运行本片最小决定性验证。
2. 按影响验证其余承诺/保留能力/回归，失败修或走 A2，不能靠开始下一片掩盖未交付状态（无依赖已授权调查可续）。
3. 片终点见 phase-3 A.6；提交后按内容身份确认测试与交付内容一致。
4. 记能力/入口/结果/提交/构建身份及限制，异步展示实物（给入口按 `checklists/handoff.md` 完整评估）；闭环后自主推进下一片，用户要求暂停/验收或实际越出授权时按 RULES R11。

## 片验收与整体
- 复用 phase-2/3/4 必要动作与未变内容；不给每个小片无条件套完整大项目仪式，也不降级机器门/真实 UI/provider 要求。
- 标明作用域，如"SL-1 验收通过，整体尚有 SL-2/3"；不得把当前片 PASS 写成整个需求完成。
- 整体收尾核全部 MUST AC/跨片组合/累计回归，各片单独 PASS 不能代替必要的组合验证；发布按原授权与风险（可交付≠须上生产）。
