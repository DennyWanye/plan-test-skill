# 幂等性审查清单

适用：批量任务、消息推送、支付/扣费、文件写入、外部 API 调用、定时任务、数据迁移、Webhook 处理。
看到"遍历 + 写副作用"代码逐条追问，任何一条答不上来 = 风险点，必须补测/补逻辑：
1. 重复调用/用户重进页面/任务重跑，会不会把同一个副作用做第二遍（重复发消息、扣款、写入）？
2. 是否有 flag / 唯一键 / 去重 set 识别"已处理"？
3. "已处理"标记持久化了吗？重启/换进程后还认得，还是只存在内存里，一重启就失忆？
4. 有没有把失败的也标记成已处理，导致永远不再重试？
5. 是否有断言"跑两次，副作用次数不变"的测试？没有就补。

输出：每个命中场景记录 场景位置(file:line) → 5 问的答案 → 风险等级 → 需补的逻辑/测试。
