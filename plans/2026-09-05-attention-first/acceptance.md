# 验收：降低 plan-test 对用户注意力的占用

## 矛盾分析
- 主要矛盾：Agent 能否把用户需求自主推进到可验证的交付，减少用户反复接管流程。
- 产生原因：现有高自主开关与逐阶段确认、A2 必须批准等规则冲突；方向选择先于事实调查。
- 解决方向：统一交互边界，先调研再决策，沿用已有授权并自主完成范围内修复。
- 最小验证动作：冷启动 Agent 对“已有执行授权、计划关键假设失败但可在范围内修复”的场景，实际产出修订与验证结果，不发起重复授权请求。
- 主要方面：明确什么由 Agent 处理、什么必须由用户决定，并让所有入口遵循同一规则。

## 范围与授权
用户原始需求：读取 RunLog 下 v0.6 执行记录，依据记录优化 skill；根据需求制定 plan 后让 Agent 自行处理，最大程度节省用户注意力；决策前先调研，确保用户掌握必要信息。
本次包含本地三个 skill 入口及其共享阶段/配置、真实日志分析、行为回放与仓库验证。依据此请求执行范围内修改；不要求用户再次批准相同优化目标。保留 plan-only 和显式共创的边界。
不包含新增 gate 诊断码、修改 ledger/schema、弱化验收、远程发布。当前工作区与活跃安装均为干净的 33c297f；验证后同步本地活跃安装。只做范围内本地提交。

## AC 与预先定义的验证
| ID | 验收条件 | 地位 | 最小决定性测试 |
|---|---|---|---|
| AC-1 | 依据实际日志指出摩擦与规则根因；按事件时间区分版本并去除重复计数 | 次要 | 核对原始文件行号、日期与短摘录 |
| AC-2 | 三入口共享注意力规则；已有执行授权不重复批准 acceptance/plan/阶段/demo；范围内 A2 调研修复后继续 | 决定性 | 冷启动自主修复场景实际修改隔离样例并验证 |
| AC-3 | 必须决策时先提供事实、来源/时间、可行选项、推荐及理由、成本/风险/回滚、未知项及影响、最小问题 | 决定性 | 冷启动读取约束资料后产出完整决策简报；未知项不得伪装成已验证 |
| AC-4 | 未授权外部操作、行为缩减/目标改变、真实资源或信息阻塞不会因少打扰被擅自通过；独立工作继续 | 决定性 | 未授权外部写入及 required 测试缺设备场景 |
| AC-5 | plan-bs 保留用户要求的共创且先调查；plan-task 能恢复既有授权；显式等待不自动继续；既有门语义不变 | 次要 | 共创、先确认、跨会话恢复行为回放；结构验证与既有全套回归 |

## Assurance 摘要
信任本地用户与工具；范围内风险是注意力节约被误解成越权、虚构调研或虚报通过。最大影响只允许本地可回滚技能修改。测试在隔离临时目录进行，不接触生产和真实用户账户。
行为规则属于 Agent 指令，测试是有限场景的行为证据，不证明所有模型或任务都遵守。
